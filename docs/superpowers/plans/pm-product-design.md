# 产品设计文档 — Browser Automation Platform

> 基于 Playwright 的浏览器自动化可视化管理平台

## 1. 现状与痛点分析

### 1.1 导航与页面结构

当前仅靠顶部导航栏在页面间跳转，缺少上下文感知导航。用户在录制详情页查看执行结果后，想回到"同一录制的所有执行列表"或"同一项目的录制列表"，需要在顶部反复切换，容易迷失上下文。

### 1.2 录制详情页过载

录制详情页同时承载 timeline / codegen / network / JSON / executions 五个 tab。一次录制可能包含数十个步骤、上百条网络请求、多个执行版本，所有内容堆在一个页面内，信息密度过高，用户难以快速定位关键问题。

### 1.3 执行结果不可操作

执行详情页缺乏清晰的失败归因。用户看到一个失败步骤，需要自行对照 timeline、网络请求、代码片段去推断原因。缺少"一键对比两次执行差异"、"失败步骤自动高亮关联网络请求"等诊断能力。

### 1.4 缺少全局概览

没有仪表盘页面。用户打开系统后直接看到项目列表，无法快速了解"今天有多少执行失败了"、"哪些录制最近没跑过"、"整体通过率趋势"等运营视角的信息。

### 1.5 录制创建流程不直观

录制作为核心操作，当前入口和流程不够顺畅。用户期望"选项目 -> 输入目标 URL -> 开始录制 -> 浏览器操作 -> 保存"，任何多余的表单字段都会打断这个流畅的体验。

## 2. 信息架构

```
/ 仪表盘（Dashboard）
    ├── 今日执行概览
    ├── 通过率趋势
    ├── 最近失败的录制
    └── 活跃项目快捷入口

/projects
    ├── 项目列表（卡片式）
    └── /projects/:id
        ├── 项目概览（通过率、录制数、最近执行）
        ├── 录制列表
        └── Mock 配置

/projects/:projectId/recordings
    └── /recordings/:id
        ├── 概览 Tab（基本信息、最近执行状态、快速操作）
        ├── Timeline Tab（步骤可视化、失败高亮）
        ├── Codegen Tab（生成的 Playwright 代码）
        ├── Network Tab（请求列表、过滤）
        ├── Executions Tab（执行历史列表）
        └── /executions/:executionId
            ├── 执行摘要（状态、耗时、通过率）
            ├── 步骤详情（单步骤展开）
            ├── 对比视图（两次执行差异）
            └── 关联网络请求

/recordings/new
    └── 录制向导（选项目 -> 输入 URL -> 启动浏览器）

/settings
    ├── 全局设置
    ├── WebSocket 连接状态
    └── Mock 管理
```

### 设计原则

- **面包屑导航**替代纯顶部导航，保留上下文
- **录制详情页**保持多 tab，但新增"概览 Tab"作为默认入口，先给结论再展开细节
- **执行详情**从录制详情页独立为子路由，支持 URL 分享

## 3. 关键用户旅程

### 旅程 A：首次录制

1. 进入系统，看到仪表盘 → 点击"新建录制"
2. 选择或创建项目（已有项目一键选择）
3. 输入目标 URL，点击"开始录制"
4. 系统启动浏览器，右侧实时显示已捕获的步骤（WebSocket 推送）
5. 用户完成操作后点击"保存"
6. 自动跳转至录制详情页，展示生成的代码和时间线

### 旅程 B：排查失败执行

1. 仪表盘显示"3 个失败" → 点击"最近失败"卡片
2. 进入失败执行的详情摘要页
3. 第一个失败步骤被高亮，显示错误信息和截图
4. 点击步骤展开，关联的网络请求自动过滤到该时间窗口
5. 切换到 Codegen Tab 查看对应代码片段
6. 确认问题后，直接在代码编辑区修改并保存

### 旅程 C：回归验证

1. 修复代码后，点击"重新执行"
2. 实时进度面板显示执行步骤（WebSocket 推送）
3. 执行完成后自动与上次失败执行对比
4. 差异视图中，之前失败的步骤显示为绿色（已修复）
5. 确认无误后关闭工单

### 旅程 D：日常巡检

1. 打开仪表盘，查看通过率趋势图
2. 浏览"最近失败的录制"列表
3. 逐个点进失败执行，快速判断是真失败还是环境波动
4. 标记误报或创建 issue 跟踪真实问题

## 4. 功能优先级

### Must Have（MVP）

- **仪表盘页面**：今日执行数、通过率、失败列表、趋势图
- **面包屑导航**：替代纯顶部导航，保留路径上下文
- **录制向导**：简化为 2 步（选项目 → 输入 URL → 开始）
- **录制详情页概览 Tab**：基本信息 + 最近执行状态 + 快捷操作
- **执行详情页**：失败步骤高亮 + 错误信息 + 截图
- **实时执行反馈**：WebSocket 推送步骤进度

### Should Have

- **执行对比视图**：两次执行步骤差异对照
- **网络请求关联**：失败步骤自动过滤关联请求
- **录制列表过滤/搜索**：按状态、时间、标签筛选
- **Mock 配置管理**：项目级 Mock 规则编辑
- **执行历史趋势**：单录制的通过率时间线

### Nice to Have

- **CI/CD 集成**：Webhook 触发执行
- **失败自动重试**：可配置重试策略
- **团队协作**：分配录制、评论、通知
- **代码片段分享**：导出单步骤代码为独立脚本
- **自定义标签系统**：按业务模块分类录制

### 布局说明

- **顶部统计卡片**（3 个）：一目了然的核心指标，带趋势对比

- 整体为 2:1 栅格布局，响应式缩为单列
