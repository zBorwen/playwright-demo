# 自主、按需的 SDD workflow

## 目标与范围

只重建项目 Agent 工作流，不修改应用功能。保留项目知识，不兼容旧固定编排或 Claude/Gemini 入口。不修改全局技能。
模型自选执行方法；可校验的完成条件和风险边界保持明确。Markdown 保存语义，YAML 保存路由和任务里程碑，不将文件格式当作强制执行机制。

## 要求与验收

- REQ-01：问答、调查不创建开发任务；明确 CSS 小改只读取目标及直接依赖，无全量文档、规格文件或独立审查要求。范围扩大时重新判断。
- REQ-02：前期只澄清影响核心验收或有实际安全/数据风险的问题。事实自行查；额外功能不加入。不默认调用完整 grilling，用户明确要求深入讨论才使用；ponytail 最小必要原则贯穿讨论、实现和审查。
- REQ-03：功能/行为变更与重构维护持久 Spec；Bug 恢复预期行为，重构保留行为不变量。明确需求后自主推进；用户变更时暂停受影响工作，未经授权的破坏性操作执行前暂停。
- REQ-04：模型决定单独、串行或并行执行；主 Agent 负责整合与验收。普通任务一次独立实现审查，重构/高风险增加设计审查，小改自检。执行者不能冒充 reviewer。
- REQ-05：状态区分类型、风险、阶段、检查结果。允许回退、暂停和有理由的不适用；实现完成不等于验证或用户验收通过。完成状态检查有效证据与当前范围摘要，缺少证据和过期记录失败。
- REQ-06：根据实际改动映射资料，未知路径显式报告；资料存在与覆盖记录可检查，不宣称证明已理解或覆盖所有语义依赖。
- REQ-07：WIP/TODO 信息原文保留在 docs/archive/legacy-planning.md，HANDOFF 只保留入口，新的进行中状态以任务 YAML 为准；长期知识保留并按影响更新；旧兼容入口移除。
- REQ-08：最小工具具有正常/失败测试，真实独立 review 有报告。工具不是宿主工具调用拦截器；没有运行校验时不能宣称有硬门禁。

## 实施方案

入口只保留约束和路由方法；workflow/routes.yaml 保存模块索引；workflow/tasks 保存较大任务状态；Python 校验器读取安全 YAML、检查声明范围与实际 Git 改动、验证证据及实现摘要。工具依赖单独列出，不改变应用依赖。
只记录里程碑，不实现复杂执行引擎、通用调度平台或强制固定节点顺序。

## 验证映射

REQ-01～04：入口/流程规则的典型场景静态检查与独立审查。
REQ-05～06、08：校验器单元测试与本任务实际校验；报告在 workflow/evidence/。
REQ-07：迁移前后原文比对及 Git diff 检查。
真实新会话的模型遵循情况不属于静态测试保证，交付时明确未验证。

## 后续修复验收（workflow-followup）

- REQ-09：任务以开始提交为基准，提交后的范围外文件仍被识别；暂存、未暂存、未跟踪和删除继续覆盖。缺失/无效基准失败。
- REQ-10：任何实际 failed 的检查阻止 done，包括小任务非强制的 design/review；na 仍按风险规则判定。
- REQ-11：HANDOFF 保持简短，历史快照完整保留且按需读取。单独更新 HANDOFF 不改变实现摘要；代码与 Spec 变化仍使证据失效。
- 验证：校验器回归测试、历史原文比对、独立实现 review。旧任务证据保持历史原样，本轮结果使用新任务记录。

## 记录减负与 HANDOFF（workflow-records）

- REQ-12：普通任务默认三份流程记录：Spec、任务 YAML、HANDOFF。verification/review 的简短证据内联 YAML；独立审查仍实际执行且记录 reviewer，摘要失效和失败门槛不变。长证据才用独立文件，不重复保存。
- REQ-13：HANDOFF 恰好一个当前任务段落，唯一指向本任务 YAML；新任务替换，旧任务只留历史链接。多个当前任务、错误链接、缺少链接均校验失败。并行由主 Agent 统一交接。
- REQ-14：用五个隔离任务验证小改、局部 Bug、普通功能、切换交接和一个可拆分的复杂任务；测试改动不合入主项目。子 Agent 统一 GPT-6.1 Sol/high。

## 可移植模板（workflow-portable）

- REQ-15：从当前规则和工具导出可移植包，仅含通用入口/流程/校验器、工具依赖与测试、空白项目约定/路由/交接、任务和规格模板。不得携带当前项目任务、报告、历史知识、凭据、依赖目录或技术栈假设。
- REQ-16：项目技术栈和命令留在 conventions，模块文档留在 routes；通用规则与导出工具共用同一份源文件，不复制维护整个核心。目标工程已有文件不得由导出器覆盖。
- REQ-17：导出包能在不同目录布局的临时 Git 项目运行 route、fingerprint、check 和通用单元测试；未知业务路径在配置路由前明确报告。验证范围为本机 Git/Python 环境，不宣称已测试所有平台或宿主。
- 非目标：自动覆盖其他项目、安装外部技能、全局模型配置、复杂插件/调度平台。

- REQ-18：移植后由 Agent 一次性分析目标项目，填写约定与路由并保留真实知识/未完成事项。新包初始化标记为 uninitialized；任务 check 拒绝未初始化状态。完成分析才标 ready 并记录基准；问答不强制初始化，后续变化仅局部更新。标记不是理解证明。
